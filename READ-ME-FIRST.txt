Pawn to Professor v1.9.8t — PUBLIC VISITOR TRACKING FIX

WHAT IT FIXES
The public visitor counter stayed at 0 because the old patch waited for:
  globalThis.state?.client

Your main app defines:
  const state = { ... }

That does not reliably expose state as globalThis.state.

This patch directly checks the existing state variable and falls back to globalThis.state only if available.

INSTALLATION
1. Upload:
   public-visitor-fix-v1.9.8t.js

2. In index.html, add this line AFTER:
   <script src="./analytics-retention-v1.9.8s.js" defer></script>

   Add:
   <script src="./public-visitor-fix-v1.9.8t.js" defer></script>

3. Redeploy Vercel.

4. Test in a PRIVATE / INCOGNITO browser window while NOT logged in.
   Open the main login page and wait about 2 seconds.

5. Log in as Admin and go to Usage Analytics → Homepage Activity → Refresh.
   Public visits should increase.

IMPORTANT
- One page load = one anonymous visit.
- A random browser ID is used for unique-browser estimates.
- No IP address is stored by this patch.
- Logged-in members are NOT counted as public visitors.
- If Supabase RPC fails, the browser console now shows the real error instead of hiding it.

MANUAL DIAGNOSTIC
Open browser console on the login page and run:
  PTP_PUBLIC_VISITOR_FIX.status()

Expected:
  clientReady: true
  loginVisible: true
  hasSession: false

To retry manually:
  PTP_PUBLIC_VISITOR_FIX.retry()

If the console then says:
  log_public_home_visit failed

the problem is in the Supabase RPC/policy rather than the browser script.
