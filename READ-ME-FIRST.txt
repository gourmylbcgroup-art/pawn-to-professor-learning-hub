Pawn to Professor v1.9.8o — 100-User Performance Preparation

GOAL
Reduce unnecessary background traffic and duplicate browser requests before
testing the Learning Hub with larger classes / up to ~100 simultaneous users.

IMPORTANT
This is preparation, not a guarantee that 100 simultaneous users will never lag.
Interactive lesson image/audio size, school Wi-Fi, Vercel usage and Supabase load
still matter and should be load-tested.

CHANGES

1. DEVICE SECURITY
   Before v1.9.8n: every 60 seconds
   v1.9.8o: every 10 minutes (600 seconds)

   With 100 visible member sessions:
   before: about 100 scheduled checks/minute
   now:    about 10 scheduled checks/minute

   The login/new-device security check is NOT removed.
   A second-device login may take up to about 10 minutes to be detected by
   the already-open first device.

2. HIDDEN TABS
   The periodic security check is skipped while the browser tab is hidden.
   This prevents inactive/background tabs from creating unnecessary traffic.

3. PORTAL SETTINGS REQUEST DE-DUPLICATION
   portal_settings is cached in memory for 60 seconds.
   The current app can request settings several times during boot/login;
   those duplicate requests now reuse the same recent result.

4. STRUCTURE REQUEST DE-DUPLICATION
   If two parts of the page ask for Years / Grades / Units at the same time,
   they share one in-flight request set instead of creating duplicate queries.
   There is NO long-lived structure cache, so new Units/Grades are not hidden
   by a stale multi-minute cache.

PRESERVED
- v1.9.8n mailbox performance improvements
- 100-message member mailbox limit
- member self-delete
- Activity Delete
- paid annual access
- manual Paid Unit Release
- Admin/Owner access
- one-device security rule
- no extra Vercel API route
